## Verification and priorities

The desktop integration tests exercise an actual local ACP subprocess that writes code through the host, requests permissions, resumes a session and runs an argument-preserving host terminal command. Denial, project escape and always-only permission requests are tested. Additional tests exercise a scripted subscription CLI through the real desktop worker with approve/deny decisions and API-key stripping, A2A/UHP discovery and request/reply, session-only credential redaction, provider attachment limits and validated harness creation. Separate tests cover direct file save conflicts, executable modes, new file staging, secrets, model streaming and local session continuation. These fixtures are not a substitute for testing each real vendor's authentication, filesystem behavior and cancellation.

Release priorities are real installed-agent/account coding validation on a clean Mac, accessibility review, and the unvalidated external integrations and the remaining bespoke management/analysis screens. The advanced Tools forms expose existing engine commands; this does not claim every terminal interaction has a bespoke native equivalent. Keep this audit as the acceptance checklist.
