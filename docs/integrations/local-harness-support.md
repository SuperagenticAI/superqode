# Local harness support audit

Checked 2026-11-09 (Europe/London), against repository tip `bd569776`. This is an integration evidence audit, not a model-quality certification.

## App eligibility

The Advanced page offers only **SuperQode Core**, **OpenCode stable 1.19.5+ within major 1**, and **Goose stable 1.58.0+ within major 1**. Missing binaries can show Not installed. Unverified versions, unwired integrations and reference-only projects are omitted, not shown as unsupported choices. The newcomer flow is unchanged.

The allowlist in `desktop_service/local_harnesses.py` includes author source URLs. Catalog RPCs, saved-profile selections, launch/preflight and Swift rendering all enforce it. A documented harness that lacks this app adapter remains hidden.

Important corrections: Codex CLI officially supports local models with `--oss` and `--local-provider ollama|lmstudio`. It stays hidden because this launcher has no reviewed Responses/output-limit adapter, not because Codex cannot run locally. Claude Code gateway documentation explicitly excludes author support for non-Claude models. Amp Custom URL requests originate from its servers, so a loopback URL is not a same-Mac integration. Antigravity SDK local support does not imply CLI/ACP support.

OpenCode is verified against release v1.19.5 config, provider and ACP source. That ACP command creates its own in-process server, whose config loader reads `OPENCODE_CONFIG_CONTENT`. Newer major/shared-server architectures are not assumed compatible. Goose is verified against release v1.58.0 provider definitions and environment/config docs. Its native Ollama adapter maps the input limit to `num_ctx` and output to `num_predict`; its LM Studio adapter uses its documented host and chat-completions endpoint. No OpenAI-model-name routing heuristic or global config edit is needed.

## Verdicts and limits

- **Supported (documented)**: positive author evidence for local inference or a compatible provider mechanism. It does not automatically make a runnable SuperQode integration.
- **Unofficial or workaround only**: a bridge, generic override or interface/edition mismatch, without verified current same-Mac agent support for that interface.
- **Not supported**: no verified documented mechanism for this interface in the sources checked. This is an evidence decision, not a claim that the project could never be adapted.
- Public docs can omit minimum versions. Unstated requirements remain unverified rather than invented. Only the two wired external adapters have reviewed release floors.
- Tool calling, templates and agent quality vary by model and server. The launcher checks installation, loaded model, endpoint, context and approximate fit. It does not execute a tool-quality benchmark.
- Local inference is not an OS/network sandbox. Harness tools may access the network.
- All 57 bundled ACP descriptors, every native runtime factory and every built-in/optional harness definition are represented below. IDs retain interface prefixes to avoid conflating a CLI, SDK, ACP wrapper and template. Other ecosystem-watch records are reference-only, not runnable integrations.

The machine-readable companion, `local-harness-support.json`, also records tool/agent caveats, version requirements, integration status and official-source snapshot hashes.

## Deferred verification

Entries marked unverified are deliberately excluded. Some official pages were unavailable or client-rendered, and several projects document only a generic API override or a different product/edition. Their exact local agent behavior and version requirements are not established here. No third-party tutorial or issue comment was used as positive evidence.

No external harness or model was installed or executed for this research. Python tests exercise generated settings and safety boundaries with mocks/local fixtures. Xcode builds, Swift tests and real Mac endpoint/tool checks are intentionally left to the release smoke checklist.
